## 🧠 Root Issue: `user` Might Be Temporarily Null or Outdated

Even though session restoration works, you're not explicitly exposing a `loadingComplete` or `isInitialized` flag via the `useAuth()` hook, so **any logic outside this file (e.g., route guards, page checks)** may be running **before `user` is reliably set**, especially during lifecycle transitions.

---

## ✅ Your Fix: Expose `isInitialized` via `useAuth()`

Update your context like this (👈 this is the missing piece):

### 🔧 1. Update `AuthContextType`:

```ts
interface AuthContextType {
  user: User | null;
  isLoading: boolean;
  isInitialized: boolean;
  login: (user: User, sessionToken?: string) => void;
  logout: () => void;
  updateUser: (user: User) => void;
}
```

---

### 🔧 2. Expose `isInitialized` in `AuthContext.Provider`:

```tsx
<AuthContext.Provider value={{ user, isLoading, isInitialized, login, logout, updateUser }}>
```

---

### 🔧 3. Use This in Routes or Pages:

Instead of:

```ts
if (!user?.profileComplete) {
  router.push("/auth/complete-profile");
}
```

Use this safer version:

```ts
const { user, isInitialized } = useAuth();

useEffect(() => {
  if (!isInitialized) return; // Wait for full init

  if (user && !user.profileComplete) {
    router.push("/auth/complete-profile");
  }
}, [user, isInitialized]);
```

This will **eliminate false redirects** due to premature null `user` values and fix your “looping to profile completion” issue.
